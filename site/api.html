CONTENT CREDENTIALS · C2PA


SIGN AT CAPTURE


For camera and creator apps: sign each photo or clip the moment it's taken. moon369-capture signs the file on Moon, writes C2PA Content Credentials into it with the Moonmark inside, and has Moon's time-stamp authority timestamp them. Any C2PA tool, and moon369.org/verify, then shows how it was made, by which app, and when. A file changed after capture fails the check.








ON YOUR SERVER (NODE)npm i moon369-capture sharp


import { capture } from 'moon369-capture';

const out = await capture(photo, {
  mimeType: 'image/jpeg',
  moonKey: process.env.MOON_KEY,
  signer: { certChainPem, privateKeyPem },  // your C2PA certificate
  app: { name: 'Lumen Camera' },
});
// out.bytes: the photo with Content Credentials
// out.moonmark: 1928.05.06 10:43:17.958952179






WHAT GOES INTO THE FILE


C2PA claim, signed with your certificate: this app made this exact file, as a digital capture.


Moon timestamp (RFC 3161) on that signature: C2PA tools show “Moon Timestamp Authority”.


org.moon369.moonmark: the signed Moonmark of the capture, registered under your name, with a look-alike hash so edited copies are found.


Trusted credentials need a claim signing certificate from a CA on the C2PA Trust List. Keys stay on your server; browser camera apps send the shot to their own backend. Full guide.

The Today on Moon card as an image: cycle, moon, lune and the real moon phase. Drop it into any page, app or README with one <img> tag and it stays current, refreshing every minute. phase.illumination in every response is the share of the moon's face lit by the sun at that instant, not the moon's age. Tide strength comes from the Sun-Moon angle and holds on every coast; local high-tide times depend on the coastline and are not included.

SIGNED MOONMARKS · PROOF OF WHEN


A signed Moonmark is a receipt: Moon saw this fingerprint at this exact moment. Hash your content where it lives and send only the SHA-256 fingerprint, never the content. Moon signs it with Ed25519, and anyone can check the receipt offline with the public key, without asking Moon. Signed bytes, in order, one per line: receipt, sha256: plus the hex, moonmark, unix_ns, key_id, and drand-quicknet: plus the beacon round and signature. The beacon is the latest round of drand quicknet, public randomness from the League of Entropy. Its value can't be known in advance, so it proves the receipt wasn't signed earlier, and anyone can check it offline with drand's public key. /v1/verify returns that bound as not_before. Receipts are hybrid (moonmark-receipt/3): a second signature with ML-DSA-65, NIST's post-quantum standard (FIPS 204), signs the same bytes plus the line ml-dsa-65: and its key id. A full receipt is valid only if both signatures check out. Moon is designed to upgrade its cryptography: every receipt names its version, and every version ever issued stays verifiable.

POST
/v1/tsa
RFC 3161



A standard RFC 3161 time-stamp authority. Cameras, Content Credentials (C2PA) tools, code signing and PDF signers already speak this protocol, so they can timestamp with Moon by pointing at this URL. Send a DER TimeStampReq (SHA-256, SHA-384 or SHA-512) with Content-Type: application/timestamp-query. curl -s https://api.moon369.org/v1/tsa/certs.pem -o moon.pem
openssl ts -verify -in resp.tsr -data photo.jpg -CAfile moon.pem

Every Moonmark returns accuracy_ns and clock, so the decimals never claim more than the clock that produced them. Moon is defined from the SI second, which is set by cesium atomic clocks. Conversions use whole nanoseconds and the exact ratio of the spec, never floating-point numbers, so every implementation agrees to the last digit.




moon-precise.jsMIT


// Exact Moon timestamp, nanosecond precision (BigInt, no floating point)
const EPOCH_NS = -62165308562978611200n;  // Cycle 0, Moon 1, Lune 1, 00:00:00
const NUM = 31881600000000000n;           // 369 × 86,400 × 10⁹
const DEN = 33168757399689600n;           // 13 × mean lunation in ns
const DAY = 86400n * 1000000000n;         // Moon ns per Moon day

function moonmark(unixNs) {              // unixNs: BigInt
  const mns = (unixNs - EPOCH_NS) * NUM / DEN;
  const dayIndex = mns / DAY;
  const cycle = dayIndex / 369n;
  const dy = Number(dayIndex - cycle * 369n);
  const m = Math.floor(dy * 13 / 369);
  const day = dy - Math.ceil(m * 369 / 13) + 1;
  let r = mns - dayIndex * DAY;
  const ns = r % 1000000000n; r /= 1000000000n;
  const s = Number(r % 60n), mi = Number(r / 60n % 60n), h = Number(r / 3600n);
  const p = (x, n = 2) => String(x).padStart(n, "0");
  return `${cycle}.${p(m + 1)}.${p(day)} ${p(h)}:${p(mi)}:${p(s)}.${p(ns, 9)}`;
}
// moonmark(1794516299901000000n) → "1928.05.03 08:57:39.035909351"

// Moon reference implementation (JavaScript)
const EPOCH_MS = -62165308562978.61;      // Cycle 0, Moon 1, Lune 1, 00:00:00
const MOON_SECOND = 1.0403730490216803;   // in SI seconds
const DAY_MS = 86400000 * MOON_SECOND;
const firstDay = (m) => Math.ceil(m * 369 / 13);

function toMoon(unixMs) {
  const t = unixMs - EPOCH_MS;
  const dayIndex = Math.floor(t / DAY_MS);
  const cycle = Math.floor(dayIndex / 369);
  const dayOfCycle = dayIndex - cycle * 369;
  const m = Math.floor(dayOfCycle * 13 / 369);
  let s = (t - dayIndex * DAY_MS) / (1000 * MOON_SECOND);
  const hour = Math.floor(s / 3600); s -= hour * 3600;
  const minute = Math.floor(s / 60);
  const second = Math.floor(s - minute * 60);
  return { cycle, moon: m + 1, day: dayOfCycle - firstDay(m) + 1,
           hour, minute, second };
}

function toUnix({ cycle, moon, day, hour = 0, minute = 0, second = 0 }) {
  const days = cycle * 369 + firstDay(moon - 1) + (day - 1);
  const secs = days * 86400 + hour * 3600 + minute * 60 + second;
  return EPOCH_MS + secs * 1000 * MOON_SECOND;
}

SIGNED MOONMARKS · PROOF OF WHEN


A signed Moonmark is a receipt: Moon saw this fingerprint at this exact moment. Hash your content where it lives and send only the SHA-256 fingerprint, never the content. Moon signs it with Ed25519, and anyone can check the receipt offline with the public key, without asking Moon. Signed bytes, in order, one per line: receipt, sha256: plus the hex, moonmark, unix_ns, key_id, and drand-quicknet: plus the beacon round and signature. The beacon is the latest round of drand quicknet, public randomness from the League of Entropy. Its value can't be known in advance, so it proves the receipt wasn't signed earlier, and anyone can check it offline with drand's public key. /v1/verify returns that bound as not_before. Receipts are hybrid (moonmark-receipt/3): a second signature with ML-DSA-65, NIST's post-quantum standard (FIPS 204), signs the same bytes plus the line ml-dsa-65: and its key id. A full receipt is valid only if both signatures check out. Moon is designed to upgrade its cryptography: every receipt names its version, and every version ever issued stays verifiable.

Every Moonmark returns accuracy_ns and clock, so the decimals never claim more than the clock that produced them. Moon is defined from the SI second, which is set by cesium atomic clocks. Conversions use whole nanoseconds and the exact ratio of the spec, never floating-point numbers, so every implementation agrees to the last digit.




moon-precise.jsMIT


// Exact Moon timestamp, nanosecond precision (BigInt, no floating point)
const EPOCH_NS = -62165308562978611200n;  // Cycle 0, Moon 1, Lune 1, 00:00:00
const NUM = 31881600000000000n;           // 369 × 86,400 × 10⁹
const DEN = 33168757399689600n;           // 13 × mean lunation in ns
const DAY = 86400n * 1000000000n;         // Moon ns per Moon day

function moonmark(unixNs) {              // unixNs: BigInt
  const mns = (unixNs - EPOCH_NS) * NUM / DEN;
  const dayIndex = mns / DAY;
  const cycle = dayIndex / 369n;
  const dy = Number(dayIndex - cycle * 369n);
  const m = Math.floor(dy * 13 / 369);
  const day = dy - Math.ceil(m * 369 / 13) + 1;
  let r = mns - dayIndex * DAY;
  const ns = r % 1000000000n; r /= 1000000000n;
  const s = Number(r % 60n), mi = Number(r / 60n % 60n), h = Number(r / 3600n);
  const p = (x, n = 2) => String(x).padStart(n, "0");
  return `${cycle}.${p(m + 1)}.${p(day)} ${p(h)}:${p(mi)}:${p(s)}.${p(ns, 9)}`;
}
// moonmark(1794516299901000000n) → "1928.05.03 08:57:39.035909351"

REFERENCE CODE

// Moon reference implementation (JavaScript)
const EPOCH_MS = -62165308562978.61;      // Cycle 0, Moon 1, Lune 1, 00:00:00
const MOON_SECOND = 1.0403730490216803;   // in SI seconds
const DAY_MS = 86400000 * MOON_SECOND;
const firstDay = (m) => Math.ceil(m * 369 / 13);

function toMoon(unixMs) {
  const t = unixMs - EPOCH_MS;
  const dayIndex = Math.floor(t / DAY_MS);
  const cycle = Math.floor(dayIndex / 369);
  const dayOfCycle = dayIndex - cycle * 369;
  const m = Math.floor(dayOfCycle * 13 / 369);
  let s = (t - dayIndex * DAY_MS) / (1000 * MOON_SECOND);
  const hour = Math.floor(s / 3600); s -= hour * 3600;
  const minute = Math.floor(s / 60);
  const second = Math.floor(s - minute * 60);
  return { cycle, moon: m + 1, day: dayOfCycle - firstDay(m) + 1,
           hour, minute, second };
}

function toUnix({ cycle, moon, day, hour = 0, minute = 0, second = 0 }) {
  const days = cycle * 369 + firstDay(moon - 1) + (day - 1);
  const secs = days * 86400 + hour * 3600 + minute * 60 + second;
  return EPOCH_MS + secs * 1000 * MOON_SECOND;
}
