All endpoints are GET, need no key, and return JSON. Times are Moon time unless the field name says utc or unix.

The current Moon date, its Moonmark and the moon's phase. One answer for every caller on Earth: there is no time zone parameter because Moon has none. Never cached.

LIGHT · DARK · HOW PEOPLE LIVE THE DAY

Moon is the engine and the calendar, and every moment on it is a Moonmark. People live the day by the light: the Light counter starts at 00:00:00 at first light and counts up in Moon seconds until sunset, then Dark counts up until the next first light, which begins the next Moon day. It needs only where you stand, lat and lon, never a time zone. Add them to /v1/now, /v1/convert or /v1/m/{moonmark} to get a light object. Where the sun doesn't rise or set for weeks, the day starts at solar midnight. /v1/sun still returns the old local clock if you need to show it alongside.

PRECISION

Moonmarks carry 9 decimal places: nanoseconds. Every event gets one exact, sortable moment on the Moon engine, with no time zone to misread.

FORMAT · YEAR.MOON.DAY HH:MM:SS.NNNNNNNNN
1928.05.03 08:57:39.035909351
CLOCK SOURCETYPICAL ACCURACYCLOCK VALUE
Phone or laptop, internet-synced (NTP)about 1 msdevice-ntp
Data center, precision time protocol (PTP)microsecondsserver-ptp
GPS-disciplined atomic referencetens of nanosecondsgps

Every Moonmark returns accuracy_ns and clock, so the decimals never claim more than the clock that produced them. Moon is defined from the SI second, which is set by cesium atomic clocks. Conversions use whole nanoseconds and the exact ratio of the spec, never floating-point numbers, so every implementation agrees to the last digit.

moon-precise.jsMIT
// Exact Moon timestamp, nanosecond precision (BigInt, no floating point)
const EPOCH_NS = -62165308562978611200n;  // Year 0, Moon 1, Day 1, 00:00:00
const NUM = 31881600000000000n;           // 369 × 86,400 × 10⁹
const DEN = 33168757399689600n;           // 13 × mean lunation in ns
const DAY = 86400n * 1000000000n;         // Moon ns per Moon day

function moonmark(unixNs) {              // unixNs: BigInt
  const mns = (unixNs - EPOCH_NS) * NUM / DEN;
  const dayIndex = mns / DAY;
  const year = dayIndex / 369n;
  const dy = Number(dayIndex - year * 369n);
  const m = Math.floor(dy * 13 / 369);
  const day = dy - Math.ceil(m * 369 / 13) + 1;
  let r = mns - dayIndex * DAY;
  const ns = r % 1000000000n; r /= 1000000000n;
  const s = Number(r % 60n), mi = Number(r / 60n % 60n), h = Number(r / 3600n);
  const p = (x, n = 2) => String(x).padStart(n, "0");
  return `${year}.${p(m + 1)}.${p(day)} ${p(h)}:${p(mi)}:${p(s)}.${p(ns, 9)}`;
}
// moonmark(1794516299901000000n) → "1928.05.03 08:57:39.035909351"

REFERENCE CODE

The complete standard in both directions, MIT licensed. Copy it, port it, ship it. It gives the same result as the API. The repository also includes the full OpenAPI 3.1 spec and 64 tests: github.com/moon369org/moon-369.

moon.jsMIT
// Moon reference implementation (JavaScript)
const EPOCH_MS = -62165308562978.61;      // Year 0, Moon 1, Day 1, 00:00:00
const MOON_SECOND = 1.0403730490216803;   // in SI seconds
const DAY_MS = 86400000 * MOON_SECOND;
const firstDay = (m) => Math.ceil(m * 369 / 13);

function toMoon(unixMs) {
  const t = unixMs - EPOCH_MS;
  const dayIndex = Math.floor(t / DAY_MS);
  const year = Math.floor(dayIndex / 369);
  const dayOfYear = dayIndex - year * 369;
  const m = Math.floor(dayOfYear * 13 / 369);
  let s = (t - dayIndex * DAY_MS) / (1000 * MOON_SECOND);
  const hour = Math.floor(s / 3600); s -= hour * 3600;
  const minute = Math.floor(s / 60);
  const second = Math.floor(s - minute * 60);
  return { year, moon: m + 1, day: dayOfYear - firstDay(m) + 1,
           hour, minute, second };
}

function toUnix({ year, moon, day, hour = 0, minute = 0, second = 0 }) {
  const days = year * 369 + firstDay(moon - 1) + (day - 1);
  const secs = days * 86400 + hour * 3600 + minute * 60 + second;
  return EPOCH_MS + secs * 1000 * MOON_SECOND;
}

BRAND RULES

Your product keeps its own name and brand. The Moon name and mark belong to Moon and appear only in the badge or in plain-text references.

DO
Say it runs on Moon

"Built on Moon time" or "Uses the Moon standard" in your copy is welcome.

DO
Use the official badge

Download the badge files as provided, in dark or light.

DON'T
Don't imply endorsement

No partnership, certification or "official" claims without written approval.

DON'T
Don't alter the mark

No recoloring, stretching, effects, or using the linked O's in your own logo.

DON'T
Don't name products Moon

Product, app and domain names can't use "Moon" as their brand.

DON'T
Don't fork the constants

If you change the epoch or the Moon second, it isn't Moon time. Don't call it that.
