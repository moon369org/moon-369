SEE IT IN YOUR PRODUCT
01 · SIGNED MOONMARKS

PROOF OF CREATION

AI images, video, text, photos, designs and code all get copied. Showing that your version existed first is hard, and sending the file to a third party to prove it gives it away.

Fingerprint the file where it lives and send Moon only the fingerprint. Moon returns a signed receipt: this existed at this exact moment. Anyone can check it offline with Moon's public key.

WORKS TODAY
  • POST /v1/sign signs a SHA-256 fingerprint at this moment
  • POST /v1/verify checks a receipt, and that it matches your file
  • GET /v1/keys publishes the public key for offline checks
  • Every receipt carries a drand beacon, proving it was not signed earlier
  • Signed with Ed25519 and ML-DSA-65, NIST's post-quantum standard

Every receipt is also locked in public on the Tideline: on the XRP Ledger within about a minute, and sealed into a tide each lune, anchored on the XRP Ledger and Bitcoin.

# fingerprint, then sign the fingerprint
HASH=$(shasum -a 256 render.png | cut -d' ' -f1)
curl -X POST https://api.moon369.org/v1/sign \
  -d "{\"sha256\":\"$HASH\"}"

# keep the receipt with the file
{ "moonmark": "1928.05.05 00:40:56.209029029",
  "key_id": "…", "signature": "…" }
02 · MOONMARK

AUDIT TRAILS AND LOGS

Servers in different countries log in different zones and formats. Putting one timeline back together after an incident means converting every line first.

Stamp every event with a Moonmark. It reads the same everywhere, sorts as plain text, and keeps nanoseconds as strings so no language loses precision. Sign the events that matter most.

WORKS TODAY
  • GET /v1/moonmark marks this moment, or any unix_ns you send
  • GET /v1/convert turns Unix time or UTC into Moon time
  • npm install moon369 computes the same Moonmarks offline, with no rate limits
curl "https://api.moon369.org/v1/moonmark?unix_ns=1794665070306000000"

{ "moonmark": "1928.05.05 00:40:56.209029029",
  "moonmark_url": "https://moon369.org/m/1928.05.05-00.40.56.209029029",
  "utc": "2026-11-14T14:04:30.306000000Z",
  "clock": "client" }
03 · SIGNED MOONMARKS

CONTRACTS AND RECORDS

Proving a contract, a design brief or a record existed on a certain date usually means trusting one company's server, or handing the document to someone.

Sign the fingerprint of the final file. The document stays private, and the receipt proves that this exact version existed at that moment. Change one character and the fingerprint no longer matches.

WORKS TODAY
  • moon369.org/notarize: drop in a PDF and print a certificate with a QR code to its signed Moonmark
  • Receipts work for any file type: PDFs, spreadsheets, images, archives
  • Verification needs only the receipt, the file and Moon's public key
  • Nothing about the document is ever sent to Moon
  • POST /v1/evidence returns a statement Moon signs, for a legal or compliance file
  • moon369.org/evidence turns a receipt into a readable report and a bundle
NOTARIZE A DOCUMENT

A receipt proves when a file existed. It does not prove who wrote it or what it means, so it works alongside signatures and records, not in place of them.

# later, anyone can check this file against its receipt
HASH=$(shasum -a 256 contract.pdf | cut -d' ' -f1)
curl -X POST https://api.moon369.org/v1/verify \
  -d "{\"receipt\": $(cat receipt.json), \"sha256\":\"$HASH\"}"

{ "valid": true, "moonmark": "1928.05.05 00:40:56.209029029" }
04 · EVENT LINK + QR

GLOBAL LAUNCHES AND EVENTS

A launch "at 9 am" means dozens of different local times around the world. Every announcement ends up with a list of cities and time zones.

Name the event, pick its time, and share one link. Everyone sees a countdown and the time where they are, can add it to their calendar in one tap, and the link shows the event name when shared. Every event has its own QR code, with that moment's moon in the center, for posters, tickets and screens.

WORKS TODAY
  • Event links with a live countdown and each viewer's local time: moon369.org/m/<moonmark>?e=<name>
  • Add to calendar (Apple, Outlook) and Google Calendar buttons
  • A share card with the event name for X, iMessage and Slack, and an on-brand QR code
  • GET /v1/m/<moonmark> returns the same moment as data

05 · SIGNED MOONMARKS

AI OUTPUTS AND DATASETS

AI can now make a convincing copy of almost anything, and labels saying what is real are easy to strip. Teams also need to show which data and which model produced a result, and when.

Sign the fingerprint of every output, prompt log, dataset snapshot or model file as it is made. Each receipt pins that exact file to an exact moment, in a public log no one can rewrite, so "this existed then" holds up later.

WORKS TODAY
  • Signing is one call per file, and only the fingerprint leaves your system
  • Every receipt lands in the public Tideline within about a minute
  • Post-quantum signatures, so records stay sound for decades

Pairs with C2PA Content Credentials: the credential says what a file is, the Moonmark proves when it existed.

# sign each generated image as it is saved
for f in out/*.png; do
  H=$(shasum -a 256 "$f" | cut -d' ' -f1)
  curl -s -X POST https://api.moon369.org/v1/sign \
    -d "{\"sha256\":\"$H\"}" > "$f.moonmark.json"
done
06 · SIGNED MOONMARK + QR

ART, PRINTS AND COLLECTIBLES

A certificate of authenticity is usually a nice piece of paper anyone could reprint. Collectors have no way to check it, and artists have no way to prove when a work was finished.

Sign the master file the day the work is done, and print its signed Moonmark link as a QR code on the certificate. A collector scans it and sees SIGNED · VERIFIED, and can drop in the file to confirm it is the exact one Moon signed.

WORKS TODAY
  • Signed Moonmark links open a page that checks the signature live
  • The page checks a dropped-in file against the receipt, in the browser
  • Works for photos, prints, music, designs and any digital master
